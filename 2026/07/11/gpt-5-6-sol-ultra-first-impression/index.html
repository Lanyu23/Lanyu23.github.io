GPT-5.6 Sol Ultra 初体验：又聪明又快，额度也烧得飞快

一句话：GPT-5.6 Sol Ultra 真的有点离谱，前几天用 GPT-5.5 折腾好几天都没修好的疑难 bug，它一下就找到了问题，还顺手给我修好了。

GPT-5.6 推出之后，我也是第一时间尝试了一下。

目前我只试了 GPT-5.6 Sol 的 Ultra 模式，还没有把 Terra 和 Luna 都完整跑一遍，但这一次的体验已经让我有点克制不住，必须先写下来分享一下。

因为它真的太强了。

前几天还在欲哭无泪，现在一下就修好了

事情的反差特别明显。

前几天我还在用 GPT-5.5 修一个疑难杂症 bug。来来回回改了好几天，尝试了不少方向，代码也改了很多次，结果问题还是没有真正解决。

那种感觉真的很难受：额度一直在掉，时间一直在花，AI 也一直说“已经修复”，结果一测试还是不行。

欲哭无泪呀。

结果换到 GPT-5.6 Sol Ultra 之后，它很快就把问题找了出来，而且不是随便找个地方糊一下，而是真的定位到了原因，然后把问题修好了。

前几天反复折腾都没有成功的东西，这次一下就过了。

这种前后落差太强烈了。那一刻我的体感就两个字：离谱。

又聪明，又快，效率简直不要太高。

为什么 Sol Ultra 会让人感觉又聪明又快

体验完之后，我马上去翻了一下官方说明，结果发现 Ultra 确实不是单纯把“思考时间”拉长那么简单。

这里先把名字理清楚：Sol 是 GPT-5.6 里能力最强的模型档位，Ultra 则是推理模式，不是另一款单独的模型。

官方文档对 Ultra 的说明很直接：它会把复杂任务拆成可以并行处理的部分，再交给多个子 Agent 同时推进。一个 Agent 可以分析问题，一个 Agent 可以检查代码，另一个 Agent 可以验证方案，最后再由主 Agent 汇总结果。

所以用户体感上就会非常明显。

以前像是一个很聪明的人，从头到尾自己查、自己改、自己验证；现在更像是突然拉来了一支小队，几个人同时排查不同方向，最后再把结论汇总回来。

这也解释了为什么我这次会觉得它不只是“更聪明”，而是连推进速度都快了很多。

不过 Ultra 也不是每个任务都需要。官方同样提醒，大多数普通任务不需要 Max 或 Ultra。只有任务足够复杂，而且能拆成多个有意义的部分时，多 Agent 并行才真正有价值。

这次不只是模型变强，Codex 的协作流程也更完整了

继续翻 Codex 更新日志之后，我发现这次让我感觉“推进更快”的原因，也不只是 GPT-5.6 本身变强。Codex 最近对多 Agent 工作流做了不少补强。

首先是委派方式更可控了。

现在客户端可以按整个对话或单次任务设置多 Agent 委派策略：完全关闭、只有用户明确要求时才启用，或者允许它主动判断什么时候需要拉子 Agent 协作。

这点其实很重要。简单任务没必要突然拉出一支队伍烧额度，复杂任务又可以让它主动拆分，不用每次都由用户手动安排。

其次，子 Agent、任务和 worktree 的进度展示也更清楚了。

以前多个 Agent 在后台干活时，用户很容易不知道它们到底在做什么，是正常分析还是已经卡住。现在进度可见性更好，至少能看清每个分支正在推进哪一部分。

另外，Codex 还增加了跨 Agent 线程的 token 预算追踪，可以显示剩余额度并在预算接近耗尽时提醒。父 Agent 现在也能收到子 Agent 的真实失败信息，不会再把一次失败看成“空白但成功”的结果。

执行服务和 MCP 会话在临时断连后的恢复也更稳，远程环境对不同系统路径、Shell、AGENTS.md 发现和沙箱行为的保留也更完整。

这些听起来不像“模型智商提升”那么吸引眼球，但对真正拿 Codex 做长任务的人来说非常实用。模型负责想得更好，工作流负责让多个 Agent 不要乱跑、不要悄悄失败，也不要烧完额度之后才告诉你。

所以严格来说，我这次的惊艳体验是两部分叠加出来的：GPT-5.6 Sol 本身更强，Ultra 能调用子 Agent 并行协作，而 Codex 侧也在把这套协作流程做得更可见、更可控、更稳定。

GPT-5.6 三个模型应该怎么选

GPT-5.6 这次分成了 Sol、Terra 和 Luna 三个主要档位。官方给出的定位其实很清楚，不需要每次都无脑上最贵最强的 Sol。

Sol：疑难杂症和复杂任务交给它

Sol 是旗舰档，也是目前最强的一档。

它更适合复杂代码修改、深度源码分析、高难 bug、架构设计、研究、安全审计，以及那些需求比较模糊、需要大量判断的开放式任务。

像我这次遇到的疑难 bug，就是非常典型的 Sol 使用场景。如果问题已经折腾很久，涉及多个模块，而且普通排查方式一直找不到根因，那就可以直接让 Sol 上。

如果任务还能拆成多个并行方向，再配合 Ultra，体感就会更明显。

Terra：日常开发的主力

Terra 更像是一位务实的全能选手，也是我觉得大多数人日常开发最应该优先尝试的模型。

平时写功能、改普通 bug、读项目、检查配置、整理文档、跑测试，这些任务通常不需要 Sol 把能力拉满。Terra 保留了比较强的推理和工具使用能力，同时成本比 Sol 更低。

官方也把 Terra 定位成 GPT-5.5 日常任务的自然接替者。以前习惯交给 GPT-5.5 的工作，大部分都可以先拿 Terra 跑一遍。

如果 Terra 能稳定解决，就没有必要每次都消耗 Sol 的额度。

Luna：清晰、重复、批量的任务

Luna 是速度和成本优先的一档。

它适合目标非常明确、结果格式也很清楚的任务，比如摘要、提取、分类、格式转换、简单代码、小脚本，以及大量重复处理。

这类任务不需要模型做太多开放式判断，让 Luna 来做通常更划算。

但如果是复杂源码判断、跨模块疑难 bug，或者一开始连问题在哪都不知道，就不建议为了省额度硬上 Luna。该让 Sol 出场的时候，还是要让 Sol 出场。

参数和价格也拉开了档位

按照目前官方 API 模型页面的信息，GPT-5.6 三个档位都提供 1.05M 上下文窗口和最高 128K 输出，差别主要体现在能力定位和价格上：

  • Sol：每 100 万输入 tokens 5 美元，输出 30 美元；
  • Terra：每 100 万输入 tokens 2.5 美元，输出 15 美元；
  • Luna：每 100 万输入 tokens 1 美元，输出 6 美元。

也就是说，Terra 的价格正好是 Sol 的一半，Luna 则更适合成本敏感的批量任务。

上面这张图是我看到的一份对比整理，方向和官方目前给出的模型定位基本一致。不过模型处于快速更新阶段，具体价格、上下文和可用范围，还是要以 OpenAI 官方页面的最新信息为准。

强大的代价：额度真的更不够用了

当然，又聪明又快不是没有代价。

我这次用上 Sol Ultra 之后，最大的副作用就是：额度更紧缺了。

Ultra 会调用子 Agent 并行处理不同部分，本质上就是同时让更多 Agent 干活。任务推进得更快，排查也更全面，但 token 和额度自然也会消耗得更猛。

以前用 GPT-5.5 的时候，是一边看它修不成功，一边心疼额度；现在用 GPT-5.6 Sol Ultra，是看它飞快把问题解决了，然后回头发现额度也飞快没了。

心情很复杂。

只能说，能力是真的强，额度也是真的不经用。

什么时候才能额度自由呢？

我现在的使用思路

虽然我目前只重点体验了 Sol Ultra，但按照官方定位，我后面大概会这样分配：

  • 日常开发、普通改动、配置排错和文档工作，优先用 Terra；
  • 摘要、提取、分类、格式转换和批量小任务，用 Luna；
  • 疑难 bug、复杂源码、架构设计和真正卡住很久的问题，再让 Sol 出场；
  • 只有任务足够复杂、确实适合拆成多条路线并行时，才开启 Ultra。

这样既能吃到 GPT-5.6 的能力提升，也不至于每个小任务都把额度烧穿。

现在的感觉

几天前，我还在对着 GPT-5.5 改了半天却怎么都修不成功，整个人都快麻了。

几天后，GPT-5.6 Sol Ultra 直接把同一个疑难问题找出来并修好，这种提升真的很难不让人兴奋。

所以即使我现在还没有把三个模型全部深度体验一遍，我还是非常建议大家去试一下 GPT-5.6，尤其是手上正好有复杂项目或疑难 bug 的人。

真的聪明得不要不要的。

又聪明，又快，简直离谱。

唯一的问题就是，用完之后可能会和我一样，看着越来越少的额度陷入沉思。

希望有一天，我们都能实现额度自由。
